# LinkedIn AI News Carousel

Read references/workflow.md. Obtain account/brand preferences from local configuration. Use a real current timestamp; prefer events from 72 hours and reject over 96 hours. An article's new timestamp cannot make an old event fresh. A release needs its original date/version. Unknown/future dates and rumors fail. The 180 domain ideas never determine fixed posts.

Use public community discussions for leads and original announcements, papers or release notes for facts. Attribute vendor claims, distinguish research from deployed products, and label editorial implications. Save source URLs and event dates. Skip if no fresh substantive change qualifies.

Use writer → humanizer → independent reviewer roles where available; otherwise separate sequential passes with honest disclosure. Specialist agents have no publishing authority. Never manufacture experiences, measured results, quotes or confessions. Preserve numbers, dates, limitations and hypothetical labels through rewriting. Select natural topic terms and 2–3 relevant hashtag candidates without reach guarantees.

Humanize slide copy before generating. Use the host's configured image tool for one slide per call, with identical typography/palette/margins and explicit exact text, page number and footer. Select a PDF with 5–7 portrait slides or a multi-image post with 3–5 images by theme and format history. Vary templates across news stories; keep design coherent within a post. Narrative: hook, change, evidence, limitation, implication, closing question as appropriate. Inspect every rendered slide. A prompt alone is not a generated asset. If no image tool exists, retain copy and report the missing capability.

For PDF mode package PNGs into a single PDF in manifest order; for image mode attach the 3–5 files in explicit manifest order. Run repository build/verification helpers when available. Verify contiguous numbers and pixel identity; visually confirm the visible labels and narrative order. Multi-image mode can display as a grid; never claim it is a swipeable PDF.

Use the live Publora tool schema and copied list_connections identity. Default to draft-only. Upload the actual PDF through documented tools or authorized browser upload; verify persistence. Recheck freshness and corrections at submission. Record pending before external write, reconcile uncertain outcomes, never blindly retry. Publish only with explicit user/account authorization. Confirm published status plus actual LinkedIn URL/ID before claiming delivery.

Read-only analytics can adapt future topics; missing data stays unavailable. No automatic engagement/outreach. Respect host permissions and keep credentials outside artifacts. Return source/freshness evidence, final text, slide manifest/PDF, review result and actual draft/publish status.

Latest media policy: choose a theme-specific template each run; use either a 5–7-page PDF or 3–5 images, selected by story suitability and format history. Images can display as a grid. Verify manifest/visible numbering and attachment order. Read docs/carousels.md for adaptive templates, relevant mentions/hashtags, comment-review boundaries and controller-security research lens.


Before any ImageGen call, read [the reference-anchored workflow](references/imagegen-consistency.md). Save a design lock, approve an actual master image, reference it for every slide, and record slide-level visual QA. Keep font, size per role, weight, spacing and template fixed across the entire post. Change design between stories only.

Read references/practical-notes.md before writing: practical use cases and implementation ideas, accurate novelty classification, varied personal-note voice, then humanizer and factual review. Omit author names from captions and visuals.
